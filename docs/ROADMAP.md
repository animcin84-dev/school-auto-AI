## 1. Что показал анализ интернета

ML-прогноз спроса в столовых — рабочая мировая практика: случайный лес/LSTM
давали снижение списанных блюд на 14–52% (Sciencedirect S0959652623044232);
шведский кейс: прогноз посещаемости ≈ 0.9–1.3 тыс. € экономии за тестовый
период (S0038012121000331). Но: на МАЛЫХ выборках классика побеждает ML
(Makridakis-тенденция, towardsdatascience "Size Matters"); сложные модели
существенно переобучаются при N ≤ 300 и сходятся лишь к N ≥ 500–1000
(Nature s41746-024-01360-w); на малых табличных данных линейные модели в
пределах 1–3% от лучшего метода в большинстве задач (arXiv 2409.01635).
Для интервалов: раздельный conformal (наш текущий) — база; апгрейды под дрейф —
скользящее окно остатков (EnbPI) и адаптивная α онлайн (ACI) (arXiv 2511.13608).
Перспективное направление для оптимизатора — decision-focused learning:
обучение модели под качество РЕШЕНИЯ, а не точности; эффективно именно в
small-data/small-model задачах (Harvard teamcore; arXiv 2505.13564).

### Казахстан — главный практический сигнал
- С марта 2026 ВСЕ ~8000 школ КЗ на цифровом учёте питания «Социальный
  кошелёк» (eGov Mobile): QR/FaceID-фиксация факта выдачи, оплата поставщикам
  ТОЛЬКО по подтверждённым выданным порциям; 149 млн обедов за 2025/26
  (newtimes.kz 222616, np.kz, inform.kz e890dc, 24.kz 786316).
  → Ежедневный meals_served для нашей системы существует БЕЗ ручного счёта —
  готовый знаменатель метрик и признак для прогноза едоков.
- Единый нацстандарт питания (с 09.2025): 4-недельное сезонное меню,
  согласуемое с санврачами; «индекс несъедаемости» — если нетронуто >30% блюд,
  меню пересматривается; бракеражные комиссии (zakon.kz 6490135).
  → Наш UneatenIndex совпадает по смыслу с государственным индексом; меню
  циклично (как 25-дневный цикл FI) — цикл меню = главный признак прогноза;
  порог 30% — готовый настраиваемый алерт мониторинга.

## 2. Эксперимент на реальных данных (POC): даёт ли ML выигрыш

Задача: прогноз числа едоков (DINERS) на последних 30 днях FI-датасета
(155 дн.; train 125). Признаки причинные (только прошлое). Ridge-регрессия —
обучаемая модель (закрытая формула, чистый stdlib): признаки — история этого
меню, история этого дня недели, вчера, MA5, тренд; L2-регуляризация.

| Модель | MAE, едоков |
|---|---|
| MA5 (=текущая moving_average) | 33.25 |
| Weekday-3 (=текущая seasonal_naive) | 38.00 |
| История этого меню | 36.00 |
| **Ridge (ML)** | **29.58 (−11% к лучшей базовой)** |

Вывод (УТОЧНЁН rolling-origin оценкой): одиночный holdout показал ridge
29.6 (−11%), но многооконная проверка (3 несмещённых окна) ВСКРЫЛА
нестабильность ridge с линейным трендом (MAE до 77+ в дальнем окне — тренд
экстраполирует). Честный итог на FI: menu_history 34.3 (±4.9) и MA5 34.7
(±2.9) — лучшие; sklearn_gbdt 37.4; ridge_notrend 38.0. ML-кандидаты ПОКА
не проходят наш гейт на этом датасете — финальное решение на реальных
данных школы (≥8–12 недель). Урок: single-holdout оптимистичен; в системе
оценка теперь rolling-origin по умолчанию.

## 3. Вердикт: «настоящий ИИ/ML» — лучше или хуже?

ЛУЧШЕ, если: данные реальные и их ≥ 8–12 недель; модель-кандидат обгоняет
действующую на честном backtest; интервалы калибруются; модель не делает
самодействий. ХУЖЕ, если: обучать на нашей синтетике (выучит наши же
допущения); заменять статуса/ворота «чёрным ящиком»; требовать ML при 20–40
днях данных (переобучение по литературе неизбежно). Поэтому: ML вводится как
ДОПОЛНИТЕЛЬНЫЙ кандидат внутри существующих честных ворот, а не вместо них.
