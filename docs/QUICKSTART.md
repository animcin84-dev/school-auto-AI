# Quickstart для директора школы (5 минут)

Эта система — помощник по школьной столовой. Она **читает** данные о питании,
**считает** показатели и **предупреждает** о проблемах. Она **не** меняет меню,
не заказывает продукты и не исполняет решений — решения остаются за бракеражной
комиссией и администрацией.

Ниже — пять шагов «от нуля до сводки». Команды запускаются в терминале
из папки системы (`python3 -m sra ...`). Никаких специальных программ
устанавливать не нужно.

---

## Шаг 1. Посмотрите демонстрацию (безопасно, данные вымышленные)

```
python3 -m sra demo --dir data/demo
```

Система создаст вымышленную школьную столовую на 60 дней: обеды, порции,
отходы. Это песочница: с реальной школой ничего не связано, файлы лежат
в папке `data/demo` и их можно удалить в любой момент.

## Шаг 2. Откройте дайджест — главный экран для директора

```
python3 -m sra digest --db data/demo/demo.sqlite3 --environment demo --school-id SCH-DEMO-CAL
```

В дайджесте одним выводом:
- **отходы на тарелках** за неделю (граммов на едока);
- **качество данных** — что измерялось, а что не заполнялось;
- **порции vs Санправила РК** — «порция гарнира 180 г при норме 100–150»;
- **алерт несъедаемости** — если нетронуто более 30% блюд, меню подлежит
  пересмотру (порог нацстандарта РК); решение — за комиссией;
- **статус прогнозов** — хватает ли данных, чтобы считать вперёд.

## Шаг 3. Загрузите свои данные

Данные — это простые CSV-файлы: **сессии** (обед дня школы) и **наблюдения**
(порции и отходы в граммах). Два способа:

- по готовому шаблону: `python3 -m sra import --db my.sqlite3 --environment real --kind sessions --file sessions.csv`
- по карте соответствий для любой выгрузки (например «Социального кошелька»):
  `python3 -m sra import-map --db my.sqlite3 --environment real --file vynruzka.csv --map karta.json`
  В карте можно включить режим `aggregate`: одна строка выгрузки = одна
  выданная порция, система сама соберёт из них обед дня школы.

Пока нет своей выгрузки — используйте демо. Хранилище для реальной школы
создаётся командой `init-db --environment real`.

## Шаг 4. Проверяйте качество и нормы перед доверий числам

```
python3 -m sra quality-check --db my.sqlite3 --environment real --school-id SCH-1
python3 -m sra check-norms  --db my.sqlite3 --environment real --school-id SCH-1
```

Система честно пишет, чего ей не хватает: «не измеряли» — значит не измеряли,
цифра из догадки не появится.

## Шаг 5. Прогноз и ML — только по правилам

```
python3 -m sra ml-status --db my.sqlite3 --environment real --school-id SCH-1
python3 -m sra forecast-diners --db my.sqlite3 --environment real --school-id SCH-1
python3 -m sra ml-gate --db my.sqlite3 --environment real --school-id SCH-1 --target diners
```

`ml-status` показывает, достаточно ли данных. `forecast-diners` честно
измеряет ошибку прогноза на ваших же прошлых днях. `ml-gate` принимает модель
в работу только если она лучше действующей по формальным правилам (не менее
чем на 5% по ошибке, устойчиво по окнам времени). Пока данных меньше двух-трёх
месяцев — вердикт будет «данных недостаточно», это нормальный ответ.

---

## Чего система НЕ делает

- Не исполняет действий: любые изменения объёма приготовления — только
  **предложения**, они требуют одобрения уполномоченного лица.
- Не обещает экономию: эффект оценивается только по плану на реальных данных
  школы (сравнение «до/после» с контрольной группой по протоколу).
- Не выдаёт данные наружу и не вызывает внешние сервисы.
- Не заменяет санитарный контроль: проверка порций и алерты — сигнал
  бракеражной комиссии, а не решение.

## Тренировка для команды: репетиция года

```
python3 -m sra rehearse-year --dir data/rehearsal
```

Полный учебный год на вымышленных данных со всеми фазами протокола
(калибровка → фон → тень → вмешательство → оценка). Ворота протокола
настоящие: на шаге «вмешательство» система покажет список условий, которые
реальная школа должна подготовить (согласия, проверенный протокол измерений,
утверждённые политики и план оценки). Удобно для ознакомления сотрудников.

## Если что-то не работает

- `python3 -m sra selfcheck --db ...` — самопроверка хранилища.
- `python3 -m sra --help` — все команды по группам.
- Ошибки пишутся по-русски с кодом (например `E_COLUMN_NOT_FOUND` — колонки
  нет в файле); полное описание кодов — в `docs/`.
