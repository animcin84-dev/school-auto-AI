## 2. Lifelike-генератор: учебный год, калиброванный по РЕАЛЬНЫМ данным

`sra/demo/lifelike.py` + CLI `gen-lifelike --fi-xlsx ...`. Генерирует год
школы КЗ (1 Sep 2025 – 25 May 2026): 170 учебных дней по календарю КЗ
(каникулы/праздники из kz_calendar), 168 сессий (2 gap-дня), 672 наблюдения,
10 дефицитных дней, 2 волны болезней (13 дней, −15% едоков), 89 пропущенных
ячеек.

Ключевое отличие от прежних генераторов — **параметры шума не выдуманы**,
а ИЗМЕРЕНЫ по реальному FI-датасету (`calibrate_from_fi`, класс
REAL_OBSERVED_DERIVED, source_ref zenodo:20825233:v1):

| Параметр | Значение (измерено по FI) |
|---|---|
| фактор дня недели | Пн 0.951 … Чт 1.036 (реальный «провал понедельника») |
| остаточная CV едоков | 11.1% (после фактора дня недели) |
| AR(1) автокорреляция остатков | ρ = 0.232 |
| отход/едока | 22.9 г ± 8.2 (CV 36.0%) |
| эффект меню цикла (25 меню) | σ между меню = **28.0%** от среднего |

Явные допущения (класс ASSUMPTION, в манифесте): доля класса на обеде 0.85,
сезонность посещаемости ±3%, зимний рост отходов +8%, влияние меню на
посещаемость ±2%, волны болезней. Генератор честно ОТКАЗЫВАЕТСЯ работать без
файла калибровки (E_CALIBRATION_FILE_REQUIRED) — никаких молчаливых шумов.

## 3. P2-протокол на lifelike-годе (честные результаты на SYNTHETIC)

Полный протокол на годе (DEMO-среда): импорт → diners backtest (3 окна × 30)
→ composite (3 × 20) → promotion gate → quality → norms → digest.

Diners (MAE едоков, 3×30): ridge_notrend 9.11 (±1.6) < ma5 9.54 < **menu_history
9.58** < weekday3 9.85; ridge с трендом 28.7 (±29.8 — нестабилен, как и на FI).

**Composite (MAE г, 3×20): menu_hist-варианты побеждают на 38%**:
direct_menu_hist 1896.5 < composite_menu_hist 1901.4 << ma5 3064/3074.5 <
weekday3 3673/3687. По стоимости решения тоже menu_hist (2278 тыс.KZT_DEMO/день).
Это подтверждает механику: при выраженном цикле меню (28% — измерено на FI)
меню-условный прогноз резко сильнее скользящего среднего; на коротком ряде FI
(125 точек обучения) этот эффект утопал в шуме, на годе (168) — виден чётко.

**Promotion gate**: REJECTED — лучший ML-кандидат (ridge_notrend) лучше
контроля (menu_history) лишь на 4.93% < порога 5.00%. Воротам безразлично,
что улучшение «почти» порога: правило формальное. Вывод для школы: даже на
данных с сильной меню-структурой ridging над меню-историей не даёт
стабильного преимущества на этом объёме — рациональный статус-кво
(меню-история), честная причина отказа зафиксирована.

Quality-check: ATTENTION корректно поймал 2 gap-дня (calendar_gaps);
dish_sum_vs_total — корректный пропуск (только разбивка блюд, нет итогов);
norms: OK (все 4 компонента в нормах Санправил, per=total нормализация).

Все данные SYNTHETIC; любые MAE/вердикты — проверка механики и демонстрация
протокола, НЕ характеристики школы КЗ.

## 4. P3-1: TabPFN — заблокирован внешне, зафиксировано честно

TabPFN v2 требует torch (сотни МБ из pypi) и скачивает веса модели с
Hugging Face при первом использовании. Хост HF в разрешённом списке песочницы
отсутствует → установка/запуск невозможны. Пакет НЕ установлен, заявлений о
TabPFN-результатах нет. Идея остаётся в плане на случай снятия ограничения
сети. Смягчающий факт из литературы (PMLBmini, Nature npj 2024): на малых
табличных данных классика в пределах 1–3% от лучшего — что наши измерения и
подтверждают.

## 5. P3-2: локальный read-only дашборд (выполнено)

`sra/dashboard.py` + CLI `dashboard --db ... --environment ... [--port 8765
--bind 127.0.0.1]`. Стандартная библиотека (http.server), без зависимостей:
страницы «Обзор» (список школ), «Дайджест», «ML-статус», «Качество», «Порции
и нормы», «Алерты». Свойства:

- **только чтение**: POST → 405; ни один маршрут не пишет и не исполняет;
- привязка 127.0.0.1 по умолчанию (правило репозитория: локальные превью не
  выставляются наружу; смена — осознанным флагом);
- на каждой странице баннер среды (DEMO/OPEN/REAL) и природы данных
  (SYNTHETIC помечается явно — «числа проверяют код, не описывают школу»);
- HTML-экранирование всего пользовательского текста (тест-инъекция
  `SCH<b>X` → `SCH&lt;b&gt;X`);
- изоляция школы: чужой school_id → 404; недоступная секция → причина, а не
  число.

Проверено curl-смоком на lifelike-хранилище (index/digest/ml-status/norms/
quality = 200, чужая школа 404, POST 405) и 6 автотестами
(tests/test_dashboard.py).
