# Отчёт: этап 4 «Неопределённость и симуляционный оптимизатор»

Статус: **реализовано и покрыто тестами** (весь набор — 157 автотестов, все проходят).
Это СИМУЛЯЦИОННЫЙ контур: предложения рассчитываются, но не исполняются;
в REAL-среде любое предложение — NO_CHANGE. Реальное вмешательство остаётся
заблокированным до условий этапов 5–6.

## Формулировка задачи (зафиксирована в коде и предложении)

| Элемент | Определение |
|---|---|
| Переменная | P — плановая суммарная масса приготовления на сессию, г. Нормативная порция и меню НЕ являются переменными |
| Действия | NO_CHANGE (готовить как обычно) либо ADJUST_PREPARED_VOLUME с \|P − P0\| ≤ Δ_max |
| Неопределённость | спрос D — эмпирические сценарии (прогноз + калибровочные остатки, walk-forward, as-of на момент решения) |
| Цель | min c_w·E[max(P−D,0)]/1000 + c_s·E[max(D−P,0)]/1000; доминирование c_s > c_w обязательно |
| Жёсткие ограничения | P(D > P) ≤ α (риск нехватки); \|P − P0\| ≤ Δ_max; P ≥ 0; бюджет времени решателя |
| Решатель | детерминированный перебор сетки с точным расчётом по сценариям (без случайности) |

Все параметры — из версионированной политики (`shortage_risk_max`, `delta_max_pct_of_baseline`,
`baseline_days`, стоимости, порог значимости); валидация отклоняет нарушающие
доминирование/диапазоны. Демо-политика `POLICY-DEMO-OPT-001` явно SYNTHETIC.

## Контур отказов (каждый путь → NO_CHANGE с машиночитаемой причиной)

`REAL-среда (MODE_BLOCKED_STAGE4_REAL)` · `политика отсутствует/невалидна/не применима к среде` ·
`прогноз недоступен (COLD_START)` · `обнаружен дрейф` · `мало калибровочных остатков` ·
`базовая линия «как обычно» неизвестна` · `INFEASIBLE в разрешённых границах (+ВНИМАНИЕ
обunsafe-базовой линии ответственному; границы молча не расширяются)` · `SOLVER_TIMEOUT` ·
`улучшение ниже порога значимости` · `изменение ниже разрешения сетки`.

## Согласование конкретной версии (миграция 3)

`approve_proposal()` привязывает согласование к **хэшу содержимого** предложения:
изменение любой детали делает согласование неприменимым (`E_APPROVAL_MISMATCH`);
повторное исполнение одной версии блокируется (`E_DOUBLE_EXECUTION`); в REAL-среде
и согласования, и исполнение заблокированы (`E_APPROVALS_NOT_AVAILABLE_STAGE4`,
`E_EXECUTION_BLOCKED_STAGE4`); NO_CHANGE согласовать нечего. В DEMO это
симуляционные записи (помечены в аудите).

## Сравнение стратегий (predict-then-optimize vs простые правила)

`compare.py` на тестовом окне: `no_change` / `fixed_quantile_rule` (готовить pred+q90) /
`optimizer` (predict-then-optimize с ограничениями) + hindsight-справка `kitchen_actual`.

Результат на демо (seed 42, 60 дней; SIMULATED, не переносится на школы):
| Стратегия | стоимость/день | отходы/день, г | нехватка/день, г | дни нехватки |
|---|---|---|---|---|
| no_change | 9066.8 | 10426 | 771 | 29% |
| fixed_quantile_rule | 3679.3 | 6131 | 123 | 14% |
| **optimizer** | 4111.9 | 8224 | **0** | **0%** |

Содержательный вывод: простое правило q90 чуть дешевле, но нарушает availability чаще;
оптимизатор единственный не допускает дней нехватки (жёсткое α) и радикально дешевле
NO_CHANGE. Оба лучше «готовить как обычно». Предложение на следующий день:
−7188.8 г (−5.1%) при риске нехватки 0; экономия на сценарий = c_w·Δ/1000 = 3594.4
(совпало с ручным счётом).

## Выполненные проверки (фактические результаты)

- `python3 -m unittest discover -s tests` → **Ran 157 tests … OK**, в том числе:
  - ручное решение задачи: сценарии [100,110,130], α=0.10 → допустим только P ≥ 130,
    P* = 130, Δ = +10, improvement = 26.667, cost(P0) = 43.333 (все посчитано вручную);
  - границы: INFEASIBLE при малом Δ_max, TIMEOUT при бюджете 0, NO_CHANGE_PREFERRED
    ниже разрешения сетки, доминирование стоимостей обязательно, кэп сетки;
  - интеграционно на демо-БД: полный контракт предложения (refs, constraints, интервал
    эффекта SIMULATED, оговорки о порции/цензурировании); REAL → блокировка;
    дрейф/холодный старт/невалидная политика → NO_CHANGE;
  - путь INFEASIBLE сразу после смены режима сценария + уведомление «ВНИМАНИЕ»;
  - согласования: привязка к версии, двойное исполнение, смена версии, среда;
  - сравнение стратегий: детерминизм (два прогона идентичны), у оптимизатора
    кратчайший показатель дней нехватки, cost(optimizer) < cost(no_change).
- Независимая сверка: экономия на сценарий = 500×7188.775/1000 = 3594.3875 — совпала
  с `improvement` и `q50` интервала эффекта; решение сетки P* = lo + 56·250 — проверено.

## Что НЕ реализовано / недоступно

- Исполнение действий (даже в DEMO это только записи) — этап 6.
- стохастические решатели/ML-политики, decision-focused learning, Value of Information.
- Реальные стоимости потерь и штрафов нехватки — нужны проверенные источники (AVF-цепочка).
- Мульτησηедельные/многошкольные задачи, совместные ограничения по складу.

## Что искусственное

Политика `POLICY-DEMO-OPT-001`, стоимости, все данные демо — SYNTHETIC;
все эффекты — SIMULATED-контрфакты на эмпирических сценариях, не измеренная экономия.

## Неизвестное

- Приемлемый α и Δ_max для реальной школы (политики с документом-источником);
  реальный час решения на кухне; цена нехватки (этически и административно);
  корректность сценариев спроса при систематической цензуре.
