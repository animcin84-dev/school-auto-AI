# Аудит системы (2026-10-22) — проблемы, решения, улучшения, новый план

Аудит проведён чтением кода и целевыми прогонами; каждая проблема —
реальная (воспроизведена или указана с местом в коде). 271 тест OK после
немедленных исправлений (блок A).

## A. Найдено и ИСПРАВЛЕНО сейчас
1. **Мёртвый конфиг календаря**: `data/kz-calendar.json` существовал, но
   `load_calendar()` игнорировал его (всегда дефолты). → Исправлено: поиск
   явный путь → `SRA_KZ_CALENDAR` → `data/kz-calendar.json` вверх от cwd;
   в конфиг пишется `_source` (откуда загружено) — проверяемо.
2. **Алерты смешивали приёмы пищи**: `nutrition_alerts` считал по всем
   сессиям (завтрак+обед вместе). → Исправлено: фильтр `meal_type` (LUNCH).
3. **Несогласованность знаменателя**: `compare_phases` использовал только
   `attendance_count` без fallback на `meals_served` (в отличие от diners).
   → Исправлено: `attendance_count or meals_served`.
4. **Молчаливый UTC в import-map**: если в карте есть `derive.observed_at`,
   но нет `timezone` — время тихо в UTC (для КЗ это +5 часов ошибки).
   → Исправлено: предупреждение `W_DERIVE_UTC_FALLBACK` в отчёте импорта.
5. **Мелочи**: опечатка «calibrованный» в PHASE7; версии numpy/sklearn не
   зафиксированы в requirements-ml.txt. → Исправлено.

## B. Дефициты дизайна (не баги; решение спланировано — см. §E)
6. **menu_id живёт в notes** (regex `MENU=...` из финского файла). Меню —
   первоклассный признак прогноза, но в контракте его поля нет. Для школы КЗ
   меню-цикл будет главным признаком (4-недельный цикл нацстандарта), а
   парсинг notes — хрупок. → **Миграция 5**: поле `menu_id` в сессиях;
   все импорты (calibrated, zenodo_fi, import-map) заполняют его; diners/
   composite читают поле, notes — fallback.
7. **Семантика строк «Соцкошелька»**: выгрузка = ПОРЦИИ (события по детям),
   контракт = СЕССИИ (обед дня школы). Импорт порций как сессий — семантическая
   ошибка (наш мок так и делал!). → Опция `aggregate` в карте import-map
   (group by школа+дата → sessions с meals_served=COUNT) + честный отчёт.
8. **Продвижение модели не формализовано**: `best_by_mae` печатается, но нет
   правила «кандидат принят, если лучше действующей на ≥X% на КАЖДОМ окне
   rolling-origin». Без правила выбор остаётся ручным вкусом. →
   `promotion_gate(beat_margin, stability)` в diners; решение фиксируется в
   model_cards (кто/когда/по каким числам).
9. **Объясняющий слой отстал от новых модулей**: explain_* есть для метрик/
   прогноза/предложений, но нет для diners/composite/quality/alerts — директор
   школы не получит русский текст по ML-результатам. → 4 новых explain_* +
   read-only инструмент `ml_status` в assistant.
10. **xlsx_min и merged cells**: значение объединённой ячейки читается только
    из левого-верхнего элемента (остальные None). Для LV-файла сработало, но
    Excel-выгрузки с объединениями — риск. → Документировано; обход — CSV-путь;
    поддержка merges — по потребности (P1).

## C. Улучшения существующих модулей
11. Прогноз: квантильная (pinball) модель для распределения спроса
    оптимизатора; diners×г/едока как кандидат распределения (механика есть —
    composite) — после данных школы.
12. quality-check: сверка «Σ блюд = итог дня» как ОБЩАЯ проверка при
    многоблюдных наблюдениях (сейчас она только внутри LV-адаптера).
13. Мониторинг: дедупликация алертов (не спамить одним и тем же ежедневно).
14. CLI разросся (25+ команд) → групповые подпарсеры (косметика, P1).
15. «Quickstart для директора школы» — одна страница без жаргона (P1).

## D. Новые идеи
16. **`digest`** — недельный дайджест одним выводом: качество данных + алерты
    + статус мониторинга + свежие прогнозы, русский текст для бракеражной
    комиссии.
17. **Проверка порций по Санправилам**: наблюдаемые порции вне диапазонов
    Прил. 7 (NORM_KZ, класс уже в калибровке) → предупреждение качества
    (не ошибка): «порция гарнира 180 г при норме 100–150».
18. **Репетиция года на calibrated-генераторе**: прогнать полный протокол
    (CALIBRATION→BASELINE→SHADOW→INTERVENTION→оценка) на синтетике как
    тренинг школы до реального пилота.
19. **Экспорт отчётов** в чистый markdown/CSV для печати (без зависимостей).
20. **TabPFN-подобные foundation-модели для таблиц** — сильны на малых данных
    по литературе 2025–2026; исследовательское, только с явным разрешением
    (пакеты) и реальными данными.
