# Отчёт: этап 3 «Базовые прогнозы»

Статус: **реализовано и покрыто тестами** (весь набор — 121 автотест, все проходят).
Базовые прогнозы работают на данных любого хранилища (REAL/DEMO); при нехватке
данных — явный `DATA_NOT_READY`, фиктивной модели нет. Качество на SYNTHETIC
показывает работу кода и поведение в сценарии, **не** ожидаемую точность в школе.

## Фиксация задачи прогноза (не меняется молча)

| Параметр | Значение |
|---|---|
| Цель | `served_mass_g` — суммарная масса выданной еды за сессию (наблюдаемая величина) |
| Единица | школа × дата × тип приёма (агрегат по блюдам, только полное покрытие) |
| Горизонт | 1 приём пищи |
| Момент решения | D−1, `decision_hour` (по умолчанию 18:00) в часовом поясе школы |
| Признаки | строго `recorded_at ≤ момент решения` — as-of срезы хранилища |

Цензурирование: на днях нехватки `served` занижает полный спрос; по умолчанию такие
дни **исключены из обучения** (нерепрезентативны) и показаны отдельно в тестовых
метриках. Точность прогноза выдачи не доказывает прогноз полного спроса.

## Что создано

- `sra/forecasting/series.py` — целевой ряд, as-of снапшоты, явный учёт исключённых
  частичных дней (импутация запрещена).
- `sra/forecasting/baselines.py` — наивный, сезонный наивный (медиана того же дня
  недели, `weeks`), скользящее среднее (окно) и hindsight-базовая линия «фактическая
  политика кухни» (prepared той же сессии; это НЕ прогноз).
- `sra/forecasting/score.py` — эмпирический квантиль, pinball loss, MAE, покрытие.
- `sra/forecasting/drift.py` — эвристический детектор дрейфа (медиана/MAD);
  информирует, не блокирует расчёты, требует валидации на реальных данных.
- `sra/forecasting/backtest.py` — хронологический backtest: train → калибровка →
  тест по времени; walk-forward калибровка остатков; квантили `pred_qX = pred + qX(остатки)`
  (калибровка смещения); MAE, pinball(0.1/0.5/0.9), покрытие/ширина, разрез по цензуре,
  SIMULATED-прокси решения (готовить q90 → отходы/нехватка).
- Хранилище: миграция 2 (`model_cards`), `save_model_card`/`get_model_cards`,
  `get_dataset_version`; `asof` теперь сравнивает время в UTC (корректно при разных offset).
- CLI: `python3 -m sra forecast ...`; демо-пайплайн включает прогноз и сохраняет карты моделей.

## Протокол backtest'а (защита от самообмана)

1. Разбиение строго по времени; параметры моделей фиксируются до теста (подбор
   на финальном тесте запрещён — для этого калибровочный период).
2. Каждый калибровочный/тестовый день предсказывается только своей прошлой
   историей, доступной на момент решения (поздние исправления записей не утекают —
   покрыто отдельным тестом с ревизией).
3. Интервалы — эмпирические квантили остатков калибровки. **Conformal-гарантии
   не заявляются**; фактическое покрытие проверяется на тесте и публикуется как есть.
4. Мультишкольность: модели строго по-школьные (без переноса между школами);
   утечка между группами исключена устройством baseline-моделей.

## Выполненные проверки (фактические результаты)

- `python3 -m unittest discover -s tests` → **Ran 121 tests … OK**, в том числе:
  - ручные контрольные значения backtest'а на детерминированном ряду (наивный MAE = 20,
    pinball 0.1/0.5/0.9 = 5.2/9.0/2.0, покрытие 0.8, ширина 48; сезонный — MAE 0,
    покрытие 1.0); значения квантилей пересчитаны вручную для калиброванных прогнозов;
  - тест утечки: ревизия записи, появившаяся спустя месяцы, НЕ видна backtest'у
    (наивный прогноз = доревизионное значение 15000, а не 90000);
  - `DATA_NOT_READY` при недостаточной истории; cold start по дням и моделям;
  - дрейф: детектируется сдвиг, OK при его отсутствии, INSUFFICIENT при малых данных;
  - as-of с разными offset (UTC-семантика), карты моделей, версии датасета.
- Демо (seed 42, 60 дней): 51 точка ряда, 5 цензурированных дней, 7 частичных дней
  исключены явно; seasonal_naive MAE ≈ 2284 г против naive ≈ 14507 г и MA ≈ 10932 г —
  сезонность сценария извлекается; покрытие 0.4–0.6 < 0.8 (выброс в тесте) — отчёт
  честно показывает НЕкалиброванность интервалов вместо заявления о гарантиях.
- **Независимая сверка вне кода SRA**: прогноз сезонного наивного для 2026-11-12
  = медиана served-сумм трёх предыдущих четвергов по сырому CSV = 131000 г — совпало
  с отчётом; повторно подтверждено тестом с ручными значениями.
- REAL-хранилище с 3 сессиями: `forecast` → `DATA_NOT_READY` с причиной
  `INSUFFICIENT_HISTORY: 3 из 28` — метрик нет, модели нет.

## Что НЕ реализовано / недоступно

- Статистические модели (ETF/SARIMAX) и градиентный бустинг — по заданию только
  «если данные оправдывают»; реальных данных нет, оснований усложнять нет.
- Conformal-интервалы, decision-focused learning, Value of Information — этапы 4+.
- Аварийные сценарии многолетней истории, конкурентный backtest, шедулинг.
- Пороговые критерии «достаточности» реальных данных — протокол этапа 5, не константы.

## Что искусственное

Все числа демо-прогнозов (seed 42) — SIMULATED на SYNTHETIC-данных. Вывод
«seasonal_naive лучше» верен для сценария генератора (заданная недельная
сезонность), а не для реальных школ.

## Неизвестное

- Реальная сезонность сельских школ КЗ (меню, каникулы, пятницы), доля цензурированных
  дней, фактический час принятия решения на кухне, допустимая цена нехватки.
- Требуемое покрытие интервала для эксплуатационного решения — параметр будущей
  проверенной политики.
