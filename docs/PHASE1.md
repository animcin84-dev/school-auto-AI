## Что создано

| Модуль | Файл | Ответственность | Граница |
|---|---|---|---|
| Контракты | `sra/contracts.py` | строгий парсинг CSV-строк в типизированные записи | не «чинит» данные молча |
| CSV-ввод | `sra/csvio.py` | заголовки по шаблонам, конвертация kg→g с пометкой | не теряет колонки без ошибки |
| Валидация | `sra/validation.py` | правила качества, ошибки E_*/предупреждения W_* → quality_flags | не заполняет пропуски выдумками |
| Хранилище | `sra/store.py` | SQLite, миграции, append-only ревизии, аудит, VERIFIED-процедура, as-of | guards сред REAL/DEMO |
| Метрики | `sra/metrics.py` | 6 авторитетных показателей с происхождением | unavailable вместо догадок |
| Политики | `sra/policies.py` | версионированные политики: источник, юрисдикция, срок, проверка | синтетическая политика не VERIFIED |
| Решения | `sra/decide.py` | контракт предложения + отказ NO_CHANGE с причинами | не имитирует действие |
| Демо | `sra/demo/synthetic.py`, `sra/demo/run.py` | seed-генератор SYNTHETIC + изолированный пайплайн | сброс демо не трогает реальные данные |
| CLI | `sra/cli.py` | init-db, import, metrics, verify, revise, policies, decide, selfcheck, audit, demo | команды эксплуатации отсутствуют намеренно |

## Команды

```bash
# тесты (только stdlib, установка зависимостей не требуется)
python3 -m unittest discover -s tests

# изолированное демо (SYNTHETIC; создаёт data/demo; --reset пересоздаёт)
python3 -m sra demo --dir data/demo --seed 42 --days 60

# реальный режим
python3 -m sra init-db --db data/real/store.sqlite3 --environment real
python3 -m sra import --db data/real/store.sqlite3 --environment real \
  --kind sessions --file sessions.csv --actor <оператор> [--unit kg]
python3 -m sra metrics --db data/real/store.sqlite3 --environment real --school-id SCH-1
python3 -m sra verify --db ... --entity observation --id O-1 --verifier "ФИО" \
  --method "повзвешивание" --source-ref "журнал/дата" --actor <проверяющий>
python3 -m sra revise --db ... --entity observation --id O-1 --set plate_waste_g=4100 \
  --reason "опечатка" --recorded-at "2026-10-21T18:00:00+05:00" --actor <оператор>
python3 -m sra selfcheck --db ... --environment real
python3 -m sra audit --db ... --environment real --tail 20
```

## Ключевые гарантии (проверены тестами)

1. **Происхождение.** Сырой импорт — только `REAL_OBSERVED`/`SYNTHETIC`; `VERIFIED`
   создаётся процедурой `verify()` с проверяющим, методом и источником; SYNTHETIC
   нельзя проверить (`E_SYNTHETIC_CANNOT_BE_VERIFIED`); правка VERIFIED сбрасывает
   её в `REAL_OBSERVED` с флагом `REVERIFICATION_REQUIRED`.
2. **Изоляция сред.** Маркер среды в БД; SYNTHETIC не входит в REAL-хранилище и
   наоборот; `reset_demo()` удаляет только файлы демо с фиксированными именами.
3. **Пропуск ≠ ноль.** Пустое поле → `None`; `0` — валидное измерение.
4. **Атомарность импорта.** Батч с ошибками не записывается частично.
5. **Утечка будущего.** `store.asof(cutoff)` не видит исправлений, появившихся позже
   среза (проверено тестом и вручную).
6. **Метрики.** Агрегирование числителей/знаменателей (не среднее процентов);
   счётчики приёмов пищи один раз на сессию; TotalMeasuredWaste только по полным
   тройкам категорий; ServiceLevel с отдельным показом цензурирования;
   CostWastePerMeal без источника стоимости → `UNAVAILABLE: COST_SOURCE_ABSENT`;
   все результаты несут счётчики статусов входов и `derived_status`
   (`SIMULATED` при наличии SYNTHETIC-входов).
7. **Отказ по умолчанию.** `decide` возвращает `NO_CHANGE/NOT_EXECUTABLE` со
   стабильными кодами причин; SHADOW/OPERATIONAL заблокированы до этапов 3–5;
   NO_CHANGE явно не подтверждает безопасность текущей практики.

## Что НЕ проверено / недоступно

- PostgreSQL, FastAPI, веб-интерфейс: не развёрнуты (в песочнице нет сервера БД;
  установка зависимостей запрещена правилами репозитория без разрешения).
- Нагрузочное тестирование, конкурентная запись, резервное копирование/восстановление.
- Аутентификация/роли: CLI доверяет `--actor`; реальный контроль доступа — этап 5.
- Статистика/prognоз/оптимизация: этапы 3–4; в репозитории их НЕТ.

## Что искусственное

- Все данные демо (`data/demo`, тесты) — SYNTHETIC с seed; метрики демо — SIMULATED.
- Демо-политика стоимости `POLICY-DEMO-COST-001` — синтетические значения,
  остаётся UNVERIFIED и не даёт реальных прав.
- Реальные числа в REAL-сценарии выше — рукотворная проверка ввода, не измерения школы.

## Неизвестные (требуют решений/данных, не выдумываются)

- Реальные нормативы питания, санитарные пороги, допустимый риск нехватки,
  минимальный уровень сервиса — нужны проверенные политики КЗ и школы.
- Источники стоимости (закупочные цены) для AVF/CostWastePerMeal.
- Порог достаточности данных (`min_real_sessions` сейчас инженерный = 1).
- Протокол взвешивания: точки, тара, границы категорий — до реального сбора (этап 5).
